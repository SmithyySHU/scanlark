# Scanlark Domain Rollout Plan

Status: planning draft. Do not change DNS, deploy, or cut production traffic
without explicit owner approval.

## Target Domains

- `scanlark.com`: public website, service information and legal pages.
- `www.scanlark.com`: redirect permanently to `https://scanlark.com`.
- `app.scanlark.com`: private login, internal Operations and future SaaS app.

The private application must not be moved onto the root domain.

## Required Owner Inputs

- Public postal or correspondence address for legal pages.
- Final provider list for hosting, email, database, backups, accounting and
  any future payment tooling.
- Final data-retention choices for enquiries, client records, reports, logs,
  quotes, work orders and accounting records.
- Payment, cancellation and service-agreement terms.
- Confirmation that launch remains B2B-only.

## DNS

1. Point `scanlark.com` A record at the production reverse proxy IP.
2. Point `www.scanlark.com` A record or CNAME at the same production reverse
   proxy.
3. Point `app.scanlark.com` A record at the production reverse proxy IP.
4. Add AAAA records only if IPv6 is fully configured and tested.
5. Keep email DNS separate and preserve SPF, DKIM and DMARC records.

## HTTPS And Redirects

- Caddy should obtain certificates for all three hostnames.
- `www.scanlark.com` should redirect to `https://scanlark.com{uri}`.
- `scanlark.com` should serve only public website, legal, robots, sitemap,
  favicons and brand assets.
- `app.scanlark.com` should serve the private SPA and `/api/*`.
- HSTS can include subdomains only after `app.scanlark.com` is confirmed ready.

## Application Configuration

Production environment should be reviewed before rollout:

- `APP_URL=https://app.scanlark.com`
- `APP_BASE_URL=https://app.scanlark.com` if used
- `WEB_ORIGIN=https://app.scanlark.com`
- `API_ORIGIN=https://app.scanlark.com/api`
- `PUBLIC_CONTACT_EMAIL=contact@scanlark.com`
- `INTERNAL_ONLY_MODE=true`
- `INTERNAL_ADMIN_EMAILS` contains only approved internal operators
- `DEV_BYPASS_AUTH=false`
- strong unique `SESSION_SECRET`, `REPORT_SHARE_TOKEN_SECRET` and
  `API_INTERNAL_TOKEN`

If the public root and private app are served by different web containers later,
build-time `VITE_API_BASE` must still point the app bundle at the private API
path.

## Cookies And Sessions

- Keep the auth cookie host-only for `app.scanlark.com` where practical.
- Do not set a parent-domain cookie for `.scanlark.com` unless there is a
  documented need.
- Keep `sameSite=lax`, `httpOnly=true`, `secure=true` in production.
- Validate existing sessions after the host change; users may need to sign in
  again if the cookie host changes.

## CORS And CSP

- CORS should allow the private app origin only:
  `https://app.scanlark.com`.
- Do not add `https://scanlark.com` to authenticated API CORS unless the public
  site later needs a server-side enquiry endpoint.
- CSP for `scanlark.com` should avoid third-party analytics and tracking.
- CSP for `app.scanlark.com` must preserve current API, SSE, font and asset
  needs.
- Review the existing inline style/script allowances before tightening CSP.

## Public SEO Files

- `robots.txt` should reference `https://scanlark.com/sitemap.xml`.
- `sitemap.xml` should include public pages only.
- Canonical public URLs should use `https://scanlark.com`.
- Private routes such as `/login`, `/dashboard`, `/operations`, `/admin`,
  `/shared-reports` and `/api` should remain disallowed or absent from public
  sitemaps.

## Email And Report Links

- Public enquiry links use
  `mailto:contact@scanlark.com?subject=Website%20health%20check%20enquiry`.
- Transactional alert sender roles remain documented in
  `docs/EMAIL_DELIVERABILITY.md`.
- Report/share links generated by the private app should use
  `https://app.scanlark.com` unless a deliberate public report host is approved.
- Quotes and service agreements should use the formal identity:
  `Connor Smith, operating under the trading name Scanlark.`

## Smoke Checks

After a staged deployment and before DNS cutover:

- `https://scanlark.com` loads the public landing page.
- `https://www.scanlark.com` redirects to `https://scanlark.com`.
- `https://scanlark.com/privacy`, `/cookies`, `/terms`,
  `/website-health-check-terms`, `/methodology` and `/contact` load.
- Public CTA opens the `contact@scanlark.com` mailto.
- `https://app.scanlark.com/login` loads.
- Internal login works for an approved internal operator.
- Public registration remains unavailable.
- `/api/health` works on the app host.
- `/api/events/stream` works for an authenticated app session.
- Existing Operations pages, report previews and PDF downloads still work.
- Browser devtools show no third-party analytics, advertising pixels or
  session-recording scripts.

## Rollback

1. Restore previous DNS records or lower TTL and point traffic back to the last
   known-good host.
2. Revert Caddy host split to the previous single-domain config if needed.
3. Restore previous `APP_URL`, `WEB_ORIGIN`, `API_ORIGIN` and related
   environment variables.
4. Restart `api`, `worker`, `web` and `caddy`.
5. Re-run login, API health, Operations and report smoke checks.
6. Do not restore the database unless a deployed migration or data change caused
   the incident.
